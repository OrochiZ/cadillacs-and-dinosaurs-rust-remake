# wof_cs 侧「该做没做」：一份取证边界，不是设计差异

> 这份只记 **C# 移植里哪些游戏行为还没落地**，用途是回答「谈 wof 设计时，哪些 C# 侧证据不能用」。
> 它**不是**「wof 原机缺什么」——原机有没有，不从这里推，也不评两款游戏优劣。
> 源码在 `g:/wof/wt1/wof_cs/src/`（本仓库之外，本机只读可达，100 个 `.cs`）；
> 本文件是 dino rep 里的可恢复索引，不改那份源码。

## 先分清哪些不是欠账

源码注释里大量「此前未移植 / 本轮已直译 / 由报警改为直译」是**修复记录**，照抄会造出假缺口：

- `Cps1Actor23Runtime.cs` 文件头写「未移植 ⇒ CS 的 0x23 是永久僵尸」，那是在解释**当初为什么要移植它**，
  同一份文件已标「全层直译」。
- `Cps1Actor26Runtime.cs:631`「由『未移植报警』改为全 9 项直译」、`:690`「改前只有一条 9 项未移植报警」。
- `Cps1Actor21Runtime.cs:190`「公共尾（本轮直译；此前是『本宿主未实现』缺口）」。
- `Cps1PlayerZhaoyun1CA46.cs:65` 甚至特意反向标注：`0x1CC80` / `0x1CC84` **不是**未移植，是复用已有直译。
- `Cps1Actor27Runtime.cs:19`「本层此前整层未移植」是**症状链**（解释 CS 侧 RNG 首差为什么落在 f=8662），
  同一文件的 `:30` 才是当前时态的「受击分支本类暂未移植」。两段要分开读。

**判据**：只认三种当前证据 —— ① 运行期会触发的报警空桩；② 注释用「仍 / 暂未 / 尚未」
且没有后续「已直译」覆盖；③ QUARANTINE 里仍未闭合的条目。

## 按玩法分块（谈 wof 设计时最容易踩的几块）

### 事件脚本 / 任务调度

- `0x0700` 协作式任务调度器、TRAP3 与用户栈**暂未整体移植**（`Cps1SystemCoroutineRuntime.cs:2591`）；
  QUARANTINE 里有「结构性·最高优先」条目讲让出 / 恢复 / 等待语义未完整实现，也记了
  「单点补会恶化、已回退」这类实测否决。
  → **影响**：wof 事件脚本「谁在什么时候让出、下一拍谁接」不能只拿 C# 侧帧序当原机证据。
- 关卡命令空桩：`Cps1LevelScript.cs:1583` 的 `记录未移植关卡命令空桩_无对应ASM`，
  遇到未覆盖的关卡脚本命令只打日志、**不写任何游戏状态**（`:590` 是调用点）。
- 舞台档 / 舞台子状态 / 舞台 ObjId / 入场循环表项：`Cps1SystemCoroutineRuntime.cs` 里一批
  `记录未移植…_无对应ASM` 报警（多为 switch default 兜底，见 `:6344 / :6584 / :6828 / :8567` 等）。
  → **影响**：关卡脚本碰到未覆盖档位会退化，别把「CS 没演这段」读成「原机没有这段」。

### 玩家状态机 / 角色与多人

- 魏延、黄忠的骑马入口（ROM `0x20536` / `0x20C28`）**整段未移植**：
  `Cps1PlayerMulti.cs:249-268` 显式告警，并有界退化成沿用张飞表（注释明说会报「索引非法」而不静默乱跳）。
- `Cps1PlayerZhaoyun1CA46.cs:60-66`：赵云抓投子系统 `0x1D142`（772 字节）及其连带的
  `0x1D0FC` 出拳命中后投技初始化未移植，显式空桩 + 报警；注释说明只有「赵云抓住敌人」才可达。
- `Cps1PlayerMulti.cs:4020` case 0x02 空实现（`0x1E04C` 未移植）、`:4095` C=0x08 子状态机未移植。
- `Program.cs:1864`：状态表回归只验证 WRAM 解码，**不调用尚未移植的 state1/2/3 更新器**。
- 2P/3P 加入与步行入场：QUARANTINE 第 155–157 笔记「已移植但运行期不可达」「多人位图 3/5/6/7 仍不可达」；
  `Cps1SystemCoroutineRuntime.cs:2182` 还有一条用户明确授权的**开发期降级**：把未移植骑马入口降级为步行。
  → **影响**：多人、骑马、抓投这几块在 C# 侧是降级 / 不可达状态，不能拿它论证 wof 的设计本意。

### 打击逻辑 / 受击反应

- `Cps1HitReaction124CA.cs:220`：入口 `0x12562` / `0x12568` / `0x1256A` 三条指令**仍未实现**
  （另立一笔、见 QUARANTINE）。
- `Cps1Actor27Runtime.cs:30`：`+0x63(a0) != 0` 的受击分支跳 `0x42566`，本类暂未移植；`:2155` 两个目标分支未移植。
- `Cps1Actor1CRuntime.cs:499`：子链（`0x3EEA` / `0x3B94` / `0x3C6A` / `0x422E` / `0x3E12` …）未移植的部分。
- `Cps1Actor19Runtime.cs:126`：D=02 走未直译（`0x24622` / `0x23110` 尚未实现）。

  那一层不能靠单个实现反推的原因——链没接全时看到的只是门票。

### 无敌 / 免伤 / 关卡时间到（词义与证据边界，不是「原机缺什么」）

这一块最容易串错，先说清它记的**不是欠账**：谈 dino「免伤不是一块免死金牌、是一群读者各读各的」那条判断时，wof 侧的 C# 证据不能用，理由有两条。

- **`invincible` 在 wof_cs 里是另一样东西**：`Cps1EnemyAI.cs:1141-1144`、`Cps1EnemySpawn.cs:2431-2433` / `:3145-3147` 读的 `+0x78` 是**敌人对象一个逐帧递减的 byte 计时器**（注释明写 `22D40..22D46 是 byte 递减，不能把 +78 当作 word 递减`），具体用途按 wof 自身台账、本块不判；`Sdl2MainWindow.cs:500-502` 的 `切换调试无敌锁定_无对应ASM()` 是宿主调试开关，按既有 §0 边界剥掉、不进设计对照。两者都不是 dino 玩家 `+$00 = 2` 那种「在场身份档位」，拿这个英文词去两侧对照会串错对象、串错语义。
- **「关卡时间到 / 全队 HP 归零」在 C# 侧没有可对照的落地**：按现有关键词搜 `wof_cs/src`，命中的全是各对象自己的倒计时（出场尾、滞空、闪烁、状态驻留等），没有 dino `rank_time_over` 那种「时钟归零 → 同帧把所有在场玩家 HP 写 0」的链。但**这只是 C# 移植侧的检索结果，不写成「wof 原机没有 TIME OVER / 没有关卡时限」**——搜不到不等于不存在，也不能从移植侧推原机缺机制。wof 侧超时按 `notes/05-objects.md:1711` 已登记为「只把波次脚本指针拨到下一条、不清场（时间是一段不带后果的节拍）」，与 dino 的 BCD 关卡时钟本就不是同一件事，没有可对照的前提。

→ **影响**：`notes/05-objects.md` 卷末那两格关于「无敌票 / 免伤不止一把尺」的判断按 §11.0 **只登记 dino 侧**；别用 wof_cs 的 `invincible` 去印证或反驳，别把 C# 侧没搜到的链读成原机机制，更别串成两款共同架构、评优劣。本块 0 次 ROM 取证，只读 wof_cs 源码与本 rep 既有笔记。

### 复活援护 / 每帧名单 / 双人合体技（本会话新判断的取证边界，不是欠账）

本会话后半段在 dino 侧立了三条判断，谈 wof 设计时最容易被「C# 里怎么没这个」带偏。先说死：这一块**登记的不是欠账**——判据仍是上面「先分清哪些不是欠账」那三种当前证据，关键词零命中不算。

- **复活援护（分五拍落炸弹）**：按 `air strike` / `airstrike` / `respawn` + `bomb` / `0x7B65E` 等关键词只读搜 `g:/wof/wt1/wof_cs/src/`，**零命中**。dino 那套是池 B 一个不可见对象按五条记录每 12 帧落一颗（`notes/05-objects.md` 卷末「连天上来帮忙的那一下，也是分五拍落地的编舞」），本来就只登记 dino 侧；C# 侧零命中既不能写成「wof 原机没有复活支援」，也不能写成「C# 漏做了」，按 §11.0 不串、不评优劣。
- **双人合体技（两人静止重叠 90 帧、都无输入才开场）**：搜 `TagTeam` / `合体` / `stand still` 等同样**零命中**（`联合体` 是 C# 的 `LayoutKind` 术语误命中，不是玩法）。dino 的 `dino-rs/crates/dino-game/src/game/player_tag.rs:29-92` 触发链在 C# 侧没有可对照的落地，但这同样是 dino 侧判断；别拿「C# 里搜不到」去反推 wof 的多人设计。
- **「谁算在场」的组织法反过来是并列的、不是缺口**：dino 是每帧清空重建、玩家与物件各自登记进碰撞名单（`notes/05-objects.md` 卷末「在场不是一个属性，是每帧重新做一次的动作」压测层，本 rep 源码）；wof_cs 里读的是 `A5+0x3E1C + i*0xE0` **三个固定玩家槽**（`Cps1Actor2B2CRuntime.cs:160-166` / `:594` / `:688`、`Cps1EventObjectRuntime.cs:8744`、`Cps1EnemySubs.cs:198`），`notes/02-mid.md:1091` 已把「三槽是固定扫描单元」登记为 wof 侧事实。两种组织法各自有证据，**别拿 dino 的「每帧举手」去要求 C# 侧也该这么做，也别据此评哪边更灵活**。

→ **影响**：`notes/04-state.md` 卷末「第二种不配合」、`notes/05-objects.md` 卷末「空袭编舞 / 在场是每帧动作」这三条判断按 §11.0 **只登记 dino 侧**；谈 wof 设计时 C# 侧的零命中不能当证据，固定三槽扫描也不能当「wof 少了点什么」。本块 0 次 ROM 取证、只读 `g:/wof/wt1/wof_cs/src/` 与本 rep 既有笔记，不改 wt1。

### 怪物策略 / 敌人对象

这一块的证据比前几块薄，得说准：C# 侧对「未覆盖的类 / 不可达的分支」用的是
**显式报警或占位**，不是静默跳过，所以「CS 侧看着不动」不等于 wof 的怪不活跃。

- `Cps1Actor16Runtime.cs:491`：`未移植 ⇒ 显式报警，不静默偷吞`（`:145` 的
  `251A ActFunc 未移植` 是当初炸掉时的实测症状，属修复动机）。
- `Cps1Actor18Runtime.cs:528-538`：`0x18B38` 任务体保留一个 `while(true) yield return 1`
  的占位协程，注释明写「本录像不可达；保留占位协程以维持『任务槽非空』这一可观察状态」——
  这是**刻意降级**，不是漏做；同文件 `:27`「宿主未实现 AI 时完全静止」是描述 FBA 基线里
  那个对象的实测表现，也不是欠账。
- 受击分支与敌人子链的当前缺口已列在上一块（`Cps1Actor27Runtime.cs:30`、
  `Cps1Actor1CRuntime.cs:499`、`Cps1Actor19Runtime.cs:126`），不在这里重复。

→ **影响**：谈 wof 怪物策略时，别用「C# 里这个对象不动 / 这条链没演」去反推原机行为；
  逐类覆盖情况以 QUARANTINE 的类目记账为准。
